Arquitectura

Visión del sistema

[ Navegador ]  React 19 · Vite · React Router
   │  Firebase Auth (cliente) → POST /api/auth/sesion → cookie HttpOnly
   │  fetch /api (mismo origen: proxy Vite / rewrites Vercel)
   ▼
[ API REST ]  Fastify en Vercel (función /api)
   │  ruta HTTP+Zod → caso de uso → puerto ← adaptador
   ├──────▶ Firebase Auth + Firestore (solo Admin SDK)
   └──────▶ Vercel Blob (comprobantes privados)
Adaptación del enunciado

El enunciado asume Next.js. Aquí: Fastify en lugar de Route Handlers y React + Vite en lugar de App Router (documentado en specs/00-vision-y-arquitectura.md).

Principio clave

Inversión de dependencias: los casos de uso no conocen Firebase ni Fastify. Los adaptadores se cablean solo en container.ts.

Seguridad

Modelo de seguridad

Identidad y autorización
  • uid solo desde sesión verificada
  • Nunca del body ni de la URL
  • Autorización por objeto en cada ruta privada
  • Guardia React ≠ seguridad real (la API decide)
Sesión y CSRF
  • Cookie HttpOnly; Secure; SameSite=Lax
  • Comprobación de Origin = WEB_ORIGIN en mutaciones
  • Bearer opcional (Bruno / pruebas)
Datos y secretos
  • Firestore: allow read, write: if false
  • Solo Admin SDK en servidor
  • Secretos fuera de Git; VITE_* solo config pública
  • Sin dangerouslySetInnerHTML
API endurecida
  • Zod en entradas
  • 415 / 413 / 429
  • Cabeceras de seguridad + CSP en estáticos
  • Blob: tipo/tamaño, pathname usuarios/<uid>/
Gastos con gráficos9
Autenticación

Flujo de inicio de sesión

  1. El usuario inicia sesión con Firebase Auth en el navegador (email/contraseña).
  2. El cliente obtiene un idToken y hace POST /api/auth/sesion.
  3. La API verifica el token con Admin SDK y emite cookie de sesión HttpOnly.
  4. Las peticiones siguientes usan la cookie; GET /api/auth/yo confirma identidad.
  5. DELETE /api/auth/sesion cierra sesión (y opcionalmente Firebase cliente).
Producción

Dominio autorizado en Firebase Auth + WEB_ORIGIN exacto en Vercel (sin comillas). El error “origen no permitido” suele ser desajuste de WEB_ORIGIN, no del usuario de prueba.
